# One Japanese learning session

Read `../japanese-assessment/SKILL.md` before evaluation. Build understanding from clear foundations and motivated connections. External research is optional; use the `researcher` subagent for a narrow uncertain claim only when delegation and its browsing tools are available. If not, continue without claiming an external check. During a closed round reveal nothing until its review. Do not ask the learner to certify the tutor's grading or pedagogical correctness.

## 1. Start only on an explicit lesson request

Call `folder_root`. If no folder is linked, ask the user to run `/link-folder "<absolute existing folder>"` and stop. Read `<root>/setup.md`; require its final `<!-- setup:complete -->` marker, accepting an existing colon-suffixed completion marker. If absent, direct the user to setup; if the file exists but is incomplete, stop for manual inspection. Never use the repository as a study root or write learner data into it. Pi loads personal preferences from the repository-root `AGENTS.md` when running here; do not treat the linked folder's README as an instruction source. Read `<root>/config.json`, `curriculum/map.json`, `progress/state.json`, `progress/summary.md`, and relevant prior record/log evidence. Resolve inconsistencies and unknown prerequisites conservatively; never infer mastery from the presence of files. Do not resume an incomplete session log or overwrite one.

Select **one main target** from the documented goal, map, and actual evidence. Use documented evidence and sound Japanese knowledge for curriculum links; check doubtful claims against a credible source when available, and leave unresolved claims uncertain rather than inventing a chapter or level. The learner may correct goals and circumstances but is not asked to approve the diagnosis. Call `start_lesson_log` with a short topic, then `study_status`. Continue only if both succeed and status reports the active lesson log. Show its exact returned path for Obsidian and explain the chosen target and evidence. If logging fails, stop before teaching or asking questions; do not invent paths or search unrelated vault folders. This is a fresh log for this session only; do not start or link another logger.

## 2. Publish material before offering evaluation

External browsing and source checks are **not prerequisites** to teaching. Use the agent's Japanese knowledge for familiar material; do not claim to have consulted a source unless you actually did. If a claim or answer is genuinely uncertain, check a credible source when available; if not, acknowledge the uncertainty, avoid a forced verdict, and do not publish that disputed claim as settled fact. Write the **complete initial lesson visibly** while the log is active: an observable goal, relevant prerequisites, grounded explanation, why the forms work, limits/contrasts, varied examples including at least one outside the learner's work context, and source links only when actually consulted. Build from understandable foundations and explain how each new form connects to what the learner already knows. The user must be able to read this material in Obsidian before any assessment prompt.

Use `ask_user_question` to offer `Ask about the material` and `Start questions` (and optionally `Finish without questions`). If they ask about the material, take one free-text question with `ask_user_question`, respond carefully without inventing facts, and offer the same choices again. Never use `ask_user_question` to grade knowledge. Only the user's explicit `Start questions` selection opens a closed round. If they finish without evaluation, record that no mastery judgment was made.

## 3. Closed evaluation and review

Use `ask_question` and the `japanese-assessment` skill. Privately plan recognition, production, application, and prerequisites relevant to the target; ask **one** well-formed question at a time and adapt from its result. Questions and answers appear in the live log; no correctness, keys, hints, scores, or explanations appear in chat, tool arguments, or the log **until the entire round ends**. Do not use any tool that instantly reveals the key. Around ten items is a planning target, not a quota; stop when varied evidence is sufficient or the limiting gap is clear. A cancelled question is not an incorrect answer. Keep question numbering per round and retain the exact prompts, options/order, answers, and the log's question/answer times for the record.

Then give one consolidated, visible review for every item: response, valid answer(s), reasoning, ambiguities, target versus incidental errors, and a cautious conclusion about this target. Check contested grammar or alternate answers when a source is available; unresolved ambiguity must not count against the learner. Do not claim an official level or durable mastery from one round. After the review, use `ask_user_question` to offer `Ask about the material`, `Try another round`, and `Finish`. Final Q&A contains no surprise questions. A new round needs new prompts and its own closed review. If the user exits early, the log remains partial and does **not** justify a progress update.

## 4. Finish while the log is still active

Only after the user chooses `Finish`, prepare final artifacts inside the linked root. **Use the guarded tools** `study_create_file`, `study_append_markdown`, `study_replace_json`, and `complete_lesson` for all session finalization writes. Do **not** create ad-hoc scripts (Python, shell, or otherwise) in the study folder, or use general-purpose `write`, `edit`, or `bash` to bypass these operations. If an operation is unsupported, report the gap rather than working around it. Tool paths are relative to the linked root; calls must be sequential, not parallel. Existing Markdown is append-only; current-state JSON can be replaced atomically; records must be created exclusively. A same-directory temporary JSON file used internally by the extension is not a learner artifact.

Read `../../../docs/spec/records.md` and create a **new dated** `records/<date>-<time>-<topic>.json` using its version 1 contract. Obtain the exact session path and captured question IDs from `study_status`. For reviewed rounds, include a judgment for every submitted answer; the tool fills the displayed task, response, opt-out, and timestamps directly from the logger. Add target/incidental judgments, alternatives, uncertainty, rationale, and sources actually consulted. On a name collision choose `-2`, `-3`, etc.; never replace a historical record.

If the learner finishes without answering assessment questions, use `evaluationStatus: "not_attempted"`, `rounds: []`, and an explicit reason. Leave `progress/state.json` byte-for-byte unchanged, including last-assessed times; append only the material covered and absence of evaluation to the progress summary. Material/reference publication and successful session completion remain allowed. Missing `rounds` is malformed data, not an implicit no-evaluation session.

For reviewed rounds, update `progress/state.json` **only from reviewed evidence**: aspects observed, `sourceRecord` equal to this record's relative path, actual assessment date, recurring mistakes only when evidenced, unknowns and next focus. Preserve other skills' prior data. If no evaluation occurred, do not invent a progress update. Append a dated explanation to `progress/summary.md` that includes the new record's relative path. Change the curriculum map only when a defensible structural reason warrants it, not merely because of one mistake.

Publish a stable reference in `materials/` for content the agent can explain confidently, whether from established knowledge or a consulted source, drawn from the lesson and resolved clarifications—not a transcript. Create a new Markdown page exclusively or append a dated correction to an existing page; never overwrite it. Link only to existing pages. Update/create a chapter index only if its referenced material exists; append to existing Markdown. Append the material link to the active session log through `study_append_markdown`. If a central claim remains genuinely doubtful, state that exception in the log/record/progress instead of publishing the disputed point as fact or claiming mastery.

After the writes, call `complete_lesson` with `recordPath` and `requiredPaths` listing every material, index, and map artifact that this session changed; the tool verifies the record, progress, summary, and specified files, then appends the completion marker as its final write. **Do not append that marker yourself.** On any failure, report it visibly while the log remains active and leave the session incomplete. After success, tell the user the session is saved and what comes next, then call `stop_lesson_log`. Stopping the logger alone never marks a lesson complete. On forced exit do not resume the partial log: the next explicit lesson trigger creates a fresh one.
